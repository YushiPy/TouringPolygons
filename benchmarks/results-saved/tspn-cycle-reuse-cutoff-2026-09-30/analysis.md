# TSPN cycle reuse and cutoff follow-up — 2026-09-30

## Objective and comparison contract

This campaign tested reuse of identical cycle relaxations across B&B nodes and reduction of oracle work once a certified pruning bound is sufficient. The formulation is a closed Euclidean tour through the supplied simple polygon regions, with free visit order and no fixed point; overlaps are allowed and holes are not represented.

Native B&B used relative gap `9.99999000001e-7` and absolute gap `0`; feasibility tolerance was `1e-8`, independent route-validation tolerance `1e-7`. Fekete reference runs used relative gap `1e-6` and matching saved SOCP/Gurobi settings. Gap is `(UB-LB)/UB`. `time_limit` denotes a valid feasible route with an open gap; process timeout is separately censored. A closed numerical B&B gap under this contract is not a zero-error rational optimality claim. Every comparison keeps closed-case timings separate from open-case gaps.

Baseline mode was CFR (`cache + features + root`), with one-tree and learned branching off. The main native comparison used a single frozen shared-memo candidate executable for each paired control and treatment. Fekete rows were reused only after input, Fekete binary, source commit, and solver-settings checks. Portfolio runs used two native workers; reused Fekete timings are reference rows only, not resource-matched or single-core parity claims.

## Single-worker hypothesis screens

The first 2 s / 8 s screen on small6 and large6 tested CFR control, +memo, +bound-first, and +both. All 48 native rows returned valid tours; every variant closed 6/6 small and 3/6 large gaps; none process-timed out. Results and per-case raw metrics are in [`analysis-screen.md`](analysis-screen.md) and [`runs/per-case-screen.csv`](runs/per-case-screen.csv).

Memo alone saw 6,124 queries with no repeated keys or hits across the two holdouts. That provides no basis for a single-worker exact-key cache benefit. Bound-first-only recorded 5,111 inherited-contact checks, 465 accepts, and 384 certified cutoff skips. The single-run paired times did not show a benefit: small6 median rose from 3.425 ms to 3.910 ms and large6 from 1.408 s to 1.483 s, with the same gap closure counts. Open-case gaps sometimes widened. Do not treat these mixed small/large medians as speedups; the per-case table carries the actual outcomes.

A floating proposal filter was then added ahead of the added inherited-contact / rational pre-KKT work. In its same-binary control versus +bound-first screen, it reduced the added inherited-contact checks to 8 (all accepted) across 12 inputs, while certified cutoff skips were 436. Of 9 cases closed in both variants, 4 were faster and 5 slower in this one-repetition sample. All three open large gaps widened: Toronto50 by 1.2725 percentage points, random60 by 0.9926 points, and tessellation60 by 0.2251 points. The filter suppresses most proposal work but has not shown a stable performance or proof-progress gain; keep `bound-first` opt-in and off by default. Detailed values are in [`analysis-filtered.md`](analysis-filtered.md) and [`runs/filtered-per-case.csv`](runs/filtered-per-case.csv).

## Shared portfolio memo

The full-geometry cache key (original label plus all binary64 polygon coordinates) is shared between the two workers only when the portfolio uses incumbent sharing. The copied result is independently revalidated outside the cache lock. `--portfolio-no-sharing` also disables cross-worker result sharing; any per-worker local memo remains. It remains opt-in.

On the 2 s / 8 s large6 portfolio screen, all six tours were valid and three gaps closed in both control and memo. Memo produced 1,341 hits from 10,913 requests. On the three jointly closed cases, OSM40 changed from 0.8455 s to 0.7153 s, random30 from 0.1727 s to 0.1735 s, and tessellation30 from 0.0353 s to 0.0245 s. Toronto50's open gap changed 11.2149% to 11.2717%; random60 and tessellation60 gaps were unchanged. This single-repetition screen is not a blanket improvement across the large set. See [`analysis-portfolio.md`](analysis-portfolio.md) and [`runs/portfolio-large6-per-case.csv`](runs/portfolio-large6-per-case.csv).

Because the portfolio screen showed actual hits and gains on two closed cases, we repeated the same 39-region São Paulo proof case (source selection `large_osm_25-40_sao_paulo_n040_seed7537`, labeled OSM39 in the campaign) three times at 10 s / 15 s. Both variants used the same binary, CFR, and two-worker cooperative portfolio. All six runs were valid and closed to the same saved lower/upper bounds. Control median was 0.8243 s (range 0.8217–0.8301); memo median was 0.7023 s (range 0.6922–0.7212), a 14.8% reduction. Memo hits were 368, 378, and 376 (median 376; mean 374) per run. This supports using memo only for a sharing-enabled portfolio, with its option default remaining false. The small screen does not show benefit for single-worker search or the no-sharing portfolio.

## Data validation and audit

The final campaign includes 90 native rows over 12 distinct inputs: 66 numerical-gap closures, 24 valid native time limits, and zero process timeouts. All 90 routes passed independent binary-rational geometry validation. No upper-bound versus recomputed-objective, lower/upper ordering, or gap-status contradiction was found. Across repeated closed results there were 237 objective-pair checks; all agreed within the existing comparison contract. Comparing each known closed objective to every same-input native interval gave 66 checks and zero contradictions. Maximum absolute objective spread was `2.84217094304e-14` (maximum relative spread `2.26641139481e-16`); maximum interval excess before tolerance was `2.84217094304e-14`. Three inputs had no closed native objective in this campaign: Toronto50, random60, and tessellation60. Full counts and tolerances are in [`provenance/all-row-objective-interval-audit.json`](provenance/all-row-objective-interval-audit.json) and its text companion.
