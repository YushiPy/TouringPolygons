# Trace and duplicate-relaxation-key inventory

The existing native CLI supports `--trace`; `UnorderedTppTraceEvent` emits `kind`, node/parent IDs, polygon `sequence`, path and bounds. `oracle` events are produced after each relaxation and carry a sequence of polygon IDs only. They do not include each internal `Element.piece` value or a canonical cycle key. The regular benchmark rows have aggregate call/cutoff counters, but no per-node state key. Therefore current saved traces cannot reliably count duplicate complete relaxation states of `(polygon, piece)` elements.

Cheapest useful instrumentation: at the `evaluate_oracle` boundary, when the full `Node.sequence` is available, form a key from ordered `(polygon,piece)` pairs. For a complete cyclic sequence, canonicalize by taking the lexicographically smallest rotation across both directions; if sequence is anchored/fixed-root, preserve that contract rather than assuming arbitrary rotation. Keep a per-solve unordered set and report key count, duplicate count, and multiplicity histogram; optionally count repeated keys with distinct node IDs. This adds no JSON trace volume and directly measures exact state repetition. If reuse includes partial B&B states, record exact partial-sequence keys separately; do not equate geometrically similar but different sequences without a separate verified equivalence rule.

For cutoff-work hypothesis, use existing `oracle_cutoff_calls` and `oracle_dual_cutoff_prunes` as baseline counters. The planned `bound-first` path should report dual-bound checks, certified cutoff sufficiencies, KKT skips, and time spent in the dual and full certificate paths. It must retain valid certified bounds and never treat a merely feasible/unverified candidate as a complete relaxation.
